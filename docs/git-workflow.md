# Git Workflow - SEDSP Backend

# Branch Strategy

## Main Branches

### main
- Stable production-ready branch
- Used for final demo and deployment

### develop
- Main development integration branch
- All features are merged here first

---

# Feature Branch Naming

Use:

```text
feature/<feature-name>
```

Examples:

```text
feature/auth
feature/product
feature/order
feature/inventory
feature/analytics
```

---

# Bug Fix Branch

```text
fix/<bug-name>
```

Example:

```text
fix/jwt-filter
fix/order-transaction
```

---

# Commit Rules

## Commit Format

```text
type: short description
```

Examples:

```text
feat: add jwt authentication
feat: create product module
fix: resolve inventory update bug
refactor: modularize order service
docs: update architecture guideline
```

---

# Commit Types

| Type | Description |
|------|-------------|
| feat | New feature |
| fix | Bug fix |
| refactor | Code restructuring |
| docs | Documentation |
| test | Testing |
| chore | Maintenance/config |

---

# Pull Request Rules

Before merging:
- Ensure project builds successfully
- Ensure no Flyway migration conflicts
- Ensure no duplicated business logic
- Review generated AI code carefully

---

# Flyway Rules

- Never modify existing migration files
- Always create new migration versions

Correct:

```text
V2__create_products.sql
V3__create_orders.sql
```

Wrong:
- Editing old migration files already pushed to Git

---

# AI Development Rules

- Never commit unreviewed AI-generated code
- Review service logic carefully
- Verify transaction boundaries
- Verify security logic manually
- Avoid duplicated logic generated by AI

---

# Team Collaboration Rules

- Pull latest develop before starting work
- Keep commits small and focused
- Push frequently
- Avoid huge feature branches
